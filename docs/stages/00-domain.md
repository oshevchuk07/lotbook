# Етап 0 — Репозиторій і домен

**Статус:** в роботі
**Мета:** налаштувати репозиторій і процес, зафіксувати доменну модель і ключові рішення до початку коду.
**Навчальні цілі:** GitHub-флоу (гілки, PR, squash, захист `main`), Conventional Commits і хуки, доменне моделювання (event storming), ADR.
**Критерій завершення (DoD):** репозиторій налаштовано, домен описано (глосарій, ER, потоки), ADR 0001–0005 прийняті, створено stage-файл для етапу 1.

## Кроки

### A. Репозиторій

- [ ] A1. Створити публічний репозиторій `lotbook` на GitHub (з опцією Add a README, щоб існувала гілка `main`), клонувати локально
- [ ] A2. Покласти стартові файли (README, CLAUDE.md, docs, шаблони) на гілці `docs/bootstrap`, відкрити PR, злити squash
- [ ] A3. Увімкнути захист `main`: мерж тільки через PR, squash merge, заборона force push
- [ ] A4. Увімкнути secret scanning і push protection (Settings → Code security)
- [ ] A5. Ініціалізувати корінь pnpm workspace (`package.json`, `pnpm-workspace.yaml`)
- [ ] A6. Додати husky: заборона комітів у `main`; commitlint для Conventional Commits
- [ ] A7. Створити milestones для етапів 0–9 і issues для кроків цього етапу

### B. Домен

- [ ] B1. Event storming на папері: події, команди, агрегати (закупівля, рух складу, продаж, повернення, збірка, інвентаризація)
- [ ] B2. Заповнити `docs/domain.md` (глосарій)
- [ ] B3. Уточнити ER-діаграму з `plan.md`
- [ ] B4. Описати ключові потоки покроково (покупка партії → залишок; продаж → комісія → прибуток; збірка; повернення)
- [ ] B5. ADR 0001: метод оцінки запасів
- [ ] B6. ADR 0002: зберігання грошей і округлення
- [ ] B7. ADR 0003: мультитенантність
- [ ] B8. ADR 0004: дизайн ledger
- [ ] B9. ADR 0005: ідентифікатори
- [ ] B10. ADR 0013: межі CQRS (де CQRS-lite, де простий CRUD)
- [ ] B11. Додати до моделі контрагентів, контакти й `Listing` (див. plan.md 3.12)
